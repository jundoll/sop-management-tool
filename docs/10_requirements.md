# 実装仕様書：AI連携型 ステップ形式SOPシステム

## 1. 目的・背景

### 1.1 システムの目的
定型業務の標準化、ヒューマンエラー防止、およびAIによる手順作成・改定の効率化を図る。

### 1.2 解決すべき課題
- 既存手順書における「表組みによるAI読み取りの阻害」
- 人力修正による負荷とミス
- 手順書の作成・改定作業の非効率性

### 1.3 期待する効果
- AIが読み取りやすい構造化されたフォーマットでのSOP管理
- システム的な「自動生成感」を排し、Excelで手作成したような標準的で可読性の高いビジネス文書を出力
- 作業者の実施手順の確実な遂行と記録の自動化

### 1.4 対象ユーザー
| 役割 | 説明 |
|------|------|
| SOP作成者 | 管理者画面を使用してSOPの作成・編集・レビュー依頼を行う |
| レビュー者 | 作成されたSOPを確認・承認する |
| 作業者（実施者） | 実施画面を使用してSOPに沿った作業を遂行し、実績を記録する |
| チェッカー | 作業者の実施をリアルタイムで目視確認する |

---

## 2. システム構成・環境

### 2.1 基盤
- **任意のWebホスティング環境（SharePoint含む）**
- ファイルシステム上で単体HTMLとして完結
- npm等のビルド環境を必要としない

### 2.2 開発形態
- **Webアプリケーション (Frontend-only)**
- Vanilla HTML/CSS/JavaScriptで構成
- npm実行環境に依存しない

### 2.3 データ保持
| 種別 | 形式 | 保存先 |
|------|------|-------|
| テンプレート | JSON形式 | ブラウザのlocalStorage |
| 実績データ | メモリ上管理 | エクスポート時のみExcel(.xlsx)生成 |

### 2.4 ブラウザ要件
- **Microsoft Edge (最新版)** を推奨
- モバイルブラウザは対象外

### 2.5 配布・ポータビリティ
- 単一フォルダ内のHTML/CSS/JSファイルで構成
- 配布時はnpm関連ファイル（package.json, tsconfig.json, node_modules等）を削除
- 他プロジェクトへファイルを渡すだけで同じシステムを再利用可能

## 3. データ構造 (JSONスキーマ定義)

```json
{
  "sop_id": "string",
  "sop_title": "string",
  "steps": [
    {
      "step_index": "integer",
      "instruction": "string",
      "media_enabled": "boolean",
      "require_time": "boolean",
      "require_judgment": "boolean",
      "skip_enabled": "boolean",
      "images": ["base64"],
      "comment": "string"
    }
  ]
}
```

### フィールド説明
| フィールド | 型 | 説明 |
|-----------|------|------|
| `sop_id` | string | SOPを一意に識別するID |
| `sop_title` | string | SOPのタイトル |
| `steps[].step_index` | integer | ステップの順序（1始まり） |
| `steps[].instruction` | string | ステップの作業指示内容 |
| `steps[].media_enabled` | boolean | 画像添付が有効かどうか |
| `steps[].require_time` | boolean | 時刻記録が必要かどうか |
| `steps[].require_judgment` | boolean | OK/NG判定が必要かどうか |
| `steps[].skip_enabled` | boolean | スキップが許可されているかどうか |
| `steps[].images` | array[string] | 参考画像（Base64）の配列 |
| `steps[].comment` | string | 作業者向けの追加コメント |

## 4. 機能要件詳細

### 4.1 管理者画面 (Admin View)

#### 4.1.1 SOP管理
- 複数SOPの作成・一覧・選択
- SOPの保存：localStorageに自動保存
- SOPの読み込み：localStorageから自動復元

#### 4.1.2 ステップ管理（CRUD）
- ステップの追加、削除
- ドラッグ＆ドロップでの並び替え

#### 4.1.3 各ステップ設定項目
- テキスト入力欄（作業指示内容の編集）
  - 広めの編集エリアを提供
  - 編集フォームは全画面またはモーダル形式で表示し、横幅を制限しないレイアウトとする
- 参考画像貼り付け（複数枚）
  - クリップボードからのペースト（貼り付け）のみ対応
- 画像プレースホルダー表示（常時ON、設定変更不可）
- 以下の制御は全ステップ共通で常時ON（設定UIは表示しない）
  - 時刻記録必須
  - OK/NG判定必須
  - スキップ許可

#### 4.1.4 プレビュー機能
- 選択中のSOPの全ステップを確認できるSOP全体プレビューを表示
- 実施画面（Player View）への遷移は行わない

### 4.2 実施画面 (Player View)

#### 4.2.1 ステップ遷移
- 1ステップ＝1画面のウィザード形式
- 「次へ」ボタンで次のステップへ進む

#### 4.2.2 入力項目
| 項目 | 入力方式 | 説明 |
|------|----------|------|
| 参照画像 | 画面表示 | 管理者が貼り付けた参考画像を表示 |
| コメント | 画面表示 | 管理者が入力した補足コメントを表示 |
| 完了時刻 | 「記録」ボタン押下 | 現在時刻(HH:mm:ss)を固定値として取得 |
| OK/NG判定 | トグル形式のボタン選択 | 2択選択 |
| 画像添付 | Ctrl+V (ペースト) | クリップボード画像を取得し、複数枚表示 |
| 作業コメント | テキスト入力 | 実施記録として自由入力 |

#### 4.2.3 例外処理
| 状況 | 動作 |
|------|------|
| スキップボタン押下 | 「理由記述エリア」が必須表示される |
| 未入力状態で「次へ」 | 警告モーダルを表示するが進行は阻害しない（**非ブロック型**） |
| プレビュー押下 | SOP全体プレビューを表示（別画面/モーダル） |
| 完了後 | 管理者一覧画面(A-01)へ遷移 |

#### 4.2.4 ネットワーク挙動
- **常時オンライン前提**（SharePoint等での配布時）
- 通信断絶時は `alert()` にて警告
- データはブラウザ内（localStorage/メモリ）で保持

## 5. 非機能要件

### 5.1 パフォーマンス
- 画面遷移時の応答時間：操作から次の画面表示まで **2秒以内**
- Excel生成時間：最大30ステップのSOPで **5秒以内**
- 画像ペーストからプレビュー表示まで **1秒以内**

### 5.2 セキュリティ
- **クリップボードAPI制約**: `navigator.clipboard.read()` を使用するため **HTTPS配信必須**
- データはブラウザのローカルストレージ（localStorage）とメモリ上で保持
- 画像データはブラウザのメモリ上でのみ保持し、ローカルファイルシステムへの保存は行わない（エクスポート時を除く）

### 5.3 ブラウザ互換性
- **Microsoft Edge (最新版)** を推奨
- モバイルブラウザは対象外

### 5.4 データ永続性
- テンプレートデータ：localStorageへ自動保存
- ブラウザのキャッシュクリア等によりデータが消失する可能性あり
- 実績データはエクスポートでのみ外部保存

### 5.5 アクセシビリティ
- キーボード操作による全機能の利用を可能とする
- スクリーンリーダー対応については将来的な検討課題とする

## 6. 出力成果物要件 (Excel Export)

### 6.1 フォーマット
- **.xlsx (OpenXML形式)**

### 6.2 レイアウト定義
- シート1枚に全工程を縦に並べる
- **列構成**: [No, 作業内容, 実施時刻, 判定, スキップ理由, コメント, 画像]
- **フォント**: 游ゴシック 11pt
- **罫線**: 標準的な細実線
- **画像配置**: 画像列には複数枚の画像を1列に縦に並べて埋め込み（セル結合で複数行にまたがる形）

### 6.3 画像最適化
- 画像添付時にJavaScriptにて以下を実施
  - **最大幅1280px** へのリサイズ
  - **JPEG品質係数0.8** での圧縮（または同等の圧縮率）
- ファイルサイズが大きくなりすぎないよう制御

## 7. 運用・ワークフロー

### 7.1 作成・実施フロー
1. 管理者が管理者画面でSOPを新規作成
2. 各SOPにステップを定義し、設定を編集
3. 作成者がTeams等でファイルを共有
4. 作業者がSOPを開き、ステップごとに作業を実行・記録
5. 全ステップ完了後、実績データをExcel出力

### 7.2 データ共有方法
- テンプレートデータはlocalStorageに保存（同一ブラウザ内で永続化）
- 実績データはExcelファイルとしてエクスポートして共有
- 別PCへのデータ移行はエクスポート/インポート機能で対応
- SOP一覧画面(選択画面)にJSONファイルからインポートするUIを提供する

### 7.3 権限管理
- ファイルシステムまたはSharePointの標準権限に依存
- 特殊なシステム内権限制御は実装しない

## 8. ユースケース

### 8.1 基本シナリオ
1. **SOP作成**: 管理者がAdmin Viewで新規SOPを作成し、ステップを定義する
2. **SOP保存**: localStorageに自動保存され、ブラウザを閉じてもデータが保持される
3. **SOP実施**: 作業者がPlayer ViewでSOPを開き、ステップごとに作業を実行・記録
4. **実績出力**: 全ステップ完了後、実績データをExcelファイルとしてエクスポート

### 8.2 例外シナリオ
| シナリオ | 期待動作 |
|----------|----------|
| ネットワーク断発生 | alert()で警告（データはlocalStorageに保持） |
| 画像ペースト失敗 | エラーメッセージを表示し、再ペーストを促す |
| ブラウザのキャッシュクリア | localStorageのデータが消失（運用でバックアップ推奨） |
| 実施途中でブラウザ閉じる | localStorageに保存済みデータは維持される（次回開時に復元） |

## 9. ドキュメント要件

### 9.1 README構成
- 1つのREADME.mdに以下を含める:
  1. 概要（システムの目的と特徴）
  2. セットアップ方法（npm不要、HTMLファイルをブラウザで開くだけ）
  3. 使い方（管理者・作業者向けの操作説明）
  4. カスタマイズ方法（機能拡張やブラウザ要件）

### 9.2 技術リスク
| リスク | 影響 | 対策案 |
|--------|------|--------|
| クリップボードAPIのブラウザ互換性 | Edge以外での動作未保証 | 対象ブラウザをEdgeに限定する方針で合意済み |
| HTTPS未配信環境でのクリップボードAPI非対応 | 画像ペースト機能が動作しない | 開発・検証環境もHTTPSで統一 |
| Excel生成ライブラリのフロントエンド制約 | 大規模データでのメモリ不足 | ライブラリ選定時にメモリ使用量を評価 |
| localStorageの容量制限 | 大量の画像データを保存できない | 画像のリサイズ・圧縮で容量削減 |

### 9.3 選定が必要な技術要素
- **Excel生成ライブラリ**: SheetJS (xlsx) CDN版
- **画像圧縮処理**: Canvas APIを使用したリサイズ・圧縮
- **UIフレームワーク**: Vanilla HTML/CSS/JavaScript (React/Vue.js不使用)
