# 実装仕様書：AI連携型 ステップ形式SOPシステム

## 1. 目的・背景

### 1.1 システムの目的
定型業務の標準化、ヒューマンエラー防止、およびAIによる手順作成・改定の効率化を図る。

### 1.2 解決すべき課題
- 既存手順書における「表組みによるAI読み取りの阻害」
- 人力修正による負荷とミス
- 手順書の作成・改定作業の非効率性

### 1.3 期待する効果
- AIが読み取りやすい構造化されたフォーマットでのSOP管理
- システム的な「自動生成感」を排し、Excelで手作成したような標準的で可読性の高いビジネス文書を出力
- 作業者の実施手順の確実な遂行と記録の自動化

### 1.4 対象ユーザー
| 役割 | 説明 |
|------|------|
| | SOP作成者 | 管理者画面を使用してSOPの作成・編集・レビュー依頼を行う |
| | レビュー者 | 作成されたSOPを確認・承認する |
| | 作業者（実施者） | 実施画面を使用してSOPに沿った作業を遂行し、実績を記録する |
| | チェッカー | 作業者の実施をリアルタイムで目視確認する |

## 2. システム構成・環境

### 2.1 基盤
- **任意のWebホスティング環境（SharePoint含む）**
- **運用環境はGitHub Pagesを想定する（HTTPS前提）**
- ファイルシステム上で単体HTMLとして完結
- npm等のビルド環境を必要としない

### 2.2 開発形態
- **Webアプリケーション (Frontend-only)**
- Vanilla HTML/CSS/JavaScriptで構成
- npm実行環境に依存しない

### 2.3 データ保持
| 種別 | 形式 | 保存先 |
|------|------|-------|
| | テンプレート | JSON形式 | ブラウザのlocalStorage |
| | 実績データ | メモリ上管理 | エクスポート時のみExcel(.xlsx)生成 |

### 2.4 ブラウザ要件
- **Microsoft Edge (最新版)** を推奨
- モバイルブラウザは対象外

### 2.5 配布・ポータビリティ
- 単一フォルダ内のHTML/CSS/JSファイルで構成
- 配布時はnpm関連ファイル（package.json, tsconfig.json, node_modules等）を削除
- 他プロジェクトへファイルを渡すだけで同じシステムを再利用可能

## 3. データ構造 (JSONスキーマ定義)

```json
{
  "sop_id": "string",
  "sop_title": "string",
  "steps": [
    {
      "step_index": "integer",
      "instruction": "string",
      "media_enabled": "boolean",
      "require_time": "boolean",
      "require_judgment": "boolean",
      "skip_enabled": "boolean",
      "images": ["base64"],
      "comment": "string"
    }
  ]
}
```

### フィールド説明
| フィールド | 型 | 説明 |
|-----------|------|------|
| `sop_id` | string | SOPを一意に識別するID |
| `sop_title` | string | SOPのタイトル |
| `steps[].step_index` | integer | ステップの順序（1始まり） |
| `steps[].instruction` | string | ステップの作業指示内容 |
| `steps[].media_enabled` | boolean | 画像添付が有効かどうか |
| `steps[].require_time` | boolean | 時刻記録が必要かどうか |
| `steps[].require_judgment` | boolean | OK/NG判定が必要かどうか |
| `steps[].skip_enabled` | boolean | スキップが許可されているかどうか |
| `steps[].evidence_required` | boolean | エビデンスの要否 |
| `steps[].evidence_description` | string | 取得するエビデンスの説明 |
| `steps[].images` | array[string] | 参考画像（Base64）の配列 |
| `steps[].comment` | string | 作業者向けの追加コメント |

### 4.3 メニューバー遷移

全画面共通のメニューバーから以下の遷移が可能。メニュー押下時は常に現在の画面状態をチェックし、未保存状態の場合はSC-06確認ダイアログを経由する。

| メニュー項目 | 遷移先 | 動作 |
|------------|-------|------|
| TOP | SC-01 TOP画面 | SOP一覧画面へ遷移 |
| SOP作成 | SC-02 作成画面 | 編集中のSOPがなければ新規作成、あればそのまま作成画面へ |
| 実施 | SC-03 実施画面 | 編集中SOPがあればそのSOPの実施画面、なければSOP選択用の一覧を表示 |

### 4.4 状態復元（リロード耐性）

| 保存状態 | 復元動作 |
|---------|---------|
| 作成画面で編集中だった | 前回編集中のSOPを復元し作成画面を再表示 |
| 実施画面で作業中だった | 前回のステップ位置と実績データを復元し実施画面を再表示 |
| それ以外 / データなし | TOP画面（SOP一覧）を表示 |

## 5. 機能要件詳細

### 5.1 TOP画面（SOP一覧画面）

#### 5.1.1 SOP一覧表示
- 登録済みSOPの一覧を表示
- 各SOPを選択してSOP作成画面または実施画面へ遷移
- 新規SOP作成ボタンを提供
- **新規作成ボタンとJSON読み込みボタンはコンパクトなレイアウトにする**
  - ボタンの縦方向の専有面積を抑え、横並びまたは最小限の高さで配置する
  - 過剰なパディングやフォントサイズを避け、標準的なボタンサイズとする
- **「SOP管理システム」のカードヘッダーエリアと「SOP一覧」エリアは1つのカードに統合する**
  - 画面上部のヘッダー的エリアをなくし、操作ボタンと一覧を同一カード内に収める
  - 「SOP管理システム」というタイトルはメニューバーのブランド表示に委ねる
- **SOP一覧、ステップ一覧、実施作業一覧のレイアウトは横長のカード型で統一する**
  - 各リストは横長カード形式のUIで統一し、視認性と操作性を高める

#### 5.1.2 JSONインポート
- JSONファイルからSOPをインポートするUIを提供
- インポート時は既存SOPを上書きせず、**新規SOPとして追加**する
- インポート後はSOP一覧を即時更新して反映する

#### 5.1.3 画面状態の保持（リロード耐性）
- ブラウザリロード時にTOP画面へ強制遷移しない
- リロード前の画面状態（編集中のSOP・実施中のSOP等）をlocalStorageに保存し、復元可能とする

### 5.2 作成画面 (Admin View)

#### 5.2.1 SOP管理
- 複数SOPの作成・一覧・選択
- SOPの保存：localStorageに自動保存
- SOPの読み込み：localStorageから自動復元
- JSONファイルからのインポート時は、SOP一覧を即時更新して反映する

#### 5.2.2 ステップ管理（CRUD）
- ステップの追加、削除
- ドラッグ＆ドロップでの並び替え
- **ステップ追加は1回の操作で1ステップのみ追加する（複数ステップが追加されるバグを修正）**
- **既存ステップ編集後の保存操作では、新規ステップが複数追加されないようにする**
- **新規ステップ作成時に指示しか指定できない。詳細レベルの内容を入れられるようにして**
- **新規ステップ追加は、一覧最下部への空ステップ追加というモーダルレス方式に変更する**
- **ステップ詳細表示での画像貼り付け操作が確実に動作するようにする（詳細表示の開閉制御を見直し、貼り付け前に詳細が閉じないようにする）**
- **詳細エリアの開閉制御を見直し、編集操作時に詳細エリアが閉じないようにする（既存バグ修正）**
  - step-itemクリックハンドラで、詳細エリア内の要素（textarea, input, .step-detail配下）をクリックした場合は詳細が閉じないようにする
  - `e.target.closest('.step-detail')` が存在する場合はtoggleをスキップする
- **新規ステップ作成時に詳細エリア（コメント・画像・エビデンス設定含む）が自動的に展開されるようにする**
  - 空ステップ追加後、自動的にstep-detailエリアを表示状態にする
- **ステップ詳細エリア内の保存ボタンも、変更が加わったときのみ有効（disabled）にする**
  - 初期表示時はdisabled、何か変更が入ったらenabled、保存後に再度disabled
- **「作成画面へ」ボタンと「キャンセル」ボタンは常時表示し、未保存時は確認ダイアログを経由する**
  - キャンセルボタンを常時表示（初期状態から `display:none` にしない）
  - 「作成画面へ」押下時は `confirmUnsavedChanges` を経由して確認ダイアログを表示
- **詳細エリアの保存・キャンセル・削除ボタンは内容に応じた幅（flex:1による引き伸ばし禁止）で横並びに配置する**
  - `flex:1` による均等割り付けを解除し、各ボタンを内容幅で表示する
  - ボタン間の余計な空白を排除する
- **実施画面の各ステップレイアウトを上下2段構成に変更する**
  - 上段: 指示内容、参照画像、補足コメント（ステップ情報）
  - 下段: 完了日付・時刻、判定ボタン（OK/NG/スキップ）、作業コメント、エビデンス画像貼り付け（実施情報）
- **ステップ編集時にステップ番号が見えなくなる問題を修正する（既存バグ修正）**
  - インライン編集（`startInlineEdit`）がイベントハンドラから呼び出されていないため、デッドコードとなっている。クリック時の動作をインライン編集または詳細エリア開閉のいずれかに統一する
  - ステップ番号（`.step-index`）は編集時も常に表示されるようにする

#### 5.2.3 各ステップ設定項目
- **新規ステップ追加は、一覧最下部への空ステップ追加というモーダルレス方式に変更する**
- テキスト入力欄（作業指示内容の編集）
  - 広めの編集エリアを提供
  - **編集ウィンドウ/モーダルを開かずにインラインで直接編集可能とする**
- 参考画像貼り付け（複数枚）
  - クリップボードからのペースト（貼り付け）のみ対応
  - 画像は十分なサイズのエリアに表示し、**拡大プレビュー（クリックで拡大）**と削除が可能とする
- **各ステップの詳細表示で、作業指示とコメントを縦に並べ、その横に画像を配置するレイアウトとする**
- **画像の貼り付けが確実に動作するようにする（詳細エリア内の画像アップロードエリアを含む）**
  - `_attachDetailPasteHandlers` 関数が定義されているが一度も実行されていないため、詳細エリア描画後に必ず呼び出されるように修正する
  - 詳細エリアの開閉や再描画後もペーストハンドラが維持されることを保証する
- **詳細を開いた後に、開閉ボタン（▼/▲）と保存・キャンセル・削除ボタンを横並びに配置し、動線に沿って使いやすく配置する**
  - 削除ボタンは保存・キャンセルボタンの近くに配置し、操作動線を最短にする
- **詳細エリアのキャンセルボタン押下時は、編集前の状態に復元する**
  - 編集中の作業指示内容・コメントは保存されず、元の値に戻る
- **保存ボタンは、変更が加わったときだけ有効（disabled）にする。変更がない場合はクリックしても保存処理が実行されない**
- 画像プレースホルダー表示（常時ON、設定変更不可）
- エビデンス設定
  - エビデンス要否（`evidence_required`）を設定可能にする
  - エビデンス説明（`evidence_description`）をテキスト入力欄で自由入力可能にする
- 以下の制御は全ステップ共通で常時ON（設定UIは表示しない）
  - 時刻記録必須
  - OK/NG判定必須
  - スキップ許可

#### 5.2.4 SOP編集画面のボタン
- SOPタイトル入力エリアの下に「保存」ボタンと「キャンセル」ボタンを横並びで配置する
- SOP新規作成時は「キャンセル」ボタンを表示し、押下で未保存のSOPを破棄して選択画面へ戻る
- SOP編集（既存SOP openedit）時も「キャンセル」ボタンを表示し、押下で編集前の状態に復元して選択画面へ戻る（未保存変更は破棄）
- **「選択画面へ」ボタンのラベルを見直し、適切な名称に変更する**

#### 5.2.5 未保存時の確認ダイアログ
- TOP画面から新規SOP作成後、保存せずに選択画面/一覧へ戻ろうとした場合、確認ダイアログを表示する
- ダイアログの選択肢：
  - **保存して戻る**：現在のSOPを保存して一覧へ戻る
  - **破棄して戻る**：保存せず一覧へ戻る（未保存SOPは破棄）
  - **キャンセル**：編集画面に留まる
- 未保存の0ステップSOPが自動的に追加されないようにする
- ステップ削除後は詳細エリアを自動的に閉じる

#### 5.2.6 画面名称
- **「管理者画面」ではなく「作成画面」という名称を使用する**
  - メニューバーの表示: 「SOP作成」
  - 画面上のタイトル表示: 「作成画面」
  - コード内のコメント・変数名等は変更しない（表示名のみ）

### 5.3 作成画面補足
- **ステップ一覧は SOP 一覧や実施作業一覧とレイアウトを統一し、カード形式で表示する**
- 詳細エリアの開閉、保存、キャンセル、削除の各操作は、モーダルを介さず同一画面内で完結させる
- **作成画面（管理者画面）ではなく「作成画面」という名称を使用する**
- **プレビューボタンは廃止する**（全ステップの閲覧・編集はステップ一覧のインライン表示で賄う）

### 5.4 実施画面 (Player View)

#### 5.4.1 画面レイアウト
- **ウィザード形式（1ステップずつ）から全ステップを一覧表示するスクロール形式に変更する**
  - 全ステップを縦に並べてスクロールで確認可能にする
  - 各ステップは1行にまとめて表示し、ユーザーが順次作業を進められるようにする
- **各ステップを上下2段構成に変更する**
  - 上段: 指示内容、参照画像、補足コメント（ステップ情報）
  - 下段: 完了日付・時刻、判定ボタン（OK/NG/スキップ）、作業コメント、スキップ理由入力、エビデンス画像貼り付け（実施情報）
  - 作業動線に沿って、上から下へ流れるレイアウトとする

#### 5.4.2 ステップ遷移
- 全ステップを1画面に表示するため、**「次へ」ボタンは不要**
- 各ステップのOK/NG/スキップ判定はその場で行い、完了時刻は自動記録する
- 作業完了後は**TOP画面（SOP一覧画面）へ戻る**

#### 5.4.3 入力項目
| 項目 | 入力方式 | 説明 |
|------|----------|------|
| 参照画像 | 画面表示（上段） | 管理者が貼り付けた参考画像を表示。**クリックで拡大表示** |
| コメント | 画面表示（上段） | 管理者が入力した補足コメントを表示 |
| 完了日付・時刻 | OK/NG/スキップ押下時に自動記録 | 現在日付（YYYY-MM-DD）と時刻（HH:mm:ss）を自動取得 |
| OK/NG判定 | トグル形式のボタン選択（下段） | 2択選択。押下で日付・時刻記録 |
| 画像添付 | Ctrl+V (ペースト)（下段） | クリップボード画像を取得し、複数枚表示。貼り付けエリアは十分なサイズを確保。**貼り付け欄に「Ctrl+Vで貼り付け」のプレースホルダーを表示**。**「ペースト」ボタンは非表示** |
| 作業コメント | テキスト入力（下段） | 実施記録として自由入力 |

#### 5.4.4 画像貼り付け・管理（実施画面）
- **エビデンス画像を貼り付けられない問題を修正する（既存バグ修正）**
- **「作業画像」横の「ペースト」ボタンを削除する**
- 貼り付け欄に「Ctrl+Vで貼り付け」のプレースホルダーテキストを表示
- 貼り付け欄のサイズを十分に大きくする
- 貼り付けた画像には削除用のバツ（×）ボタンを表示し、**押下で画像が削除されるようにする**
- 手順に貼り付けられた画像をクリックしたら拡大表示する
- エビデンス画像の貼り付けも同様にCtrl+Vで貼り付け可能とする

#### 5.4.5 スキップ機能
- 各ステップにあらかじめ**スキップ理由入力欄**を用意する（スキップボタン押下時にウィンドウ表示ではなく）
- スキップ理由を入力した上でスキップボタンを押下するとスキップされる
- スキップ時も完了時刻が自動記録される

#### 5.4.6 例外処理
| 状況 | 動作 |
|------|------|
| スキップボタン押下 | あらかじめ用意されたスキップ理由入力欄に入力後、スキップ実行 |
| 未入力状態でスキップボタン押下 | スキップ理由入力欄の近くに赤字で「スキップ理由を入力してください」とメッセージを表示する（モーダルウィンドウは使用しない）。入力を促し、スキップは実行しない |
| 完了後 | TOP画面（SOP一覧画面）へ遷移 |

#### 5.4.7 作業者名
- **実施開始画面および実施画面に作業者名の入力欄は不要とする**
- 実施開始画面は「開始」ボタンのみのシンプルな構成とする

#### 5.4.8 ネットワーク挙動
- **常時オンライン前提**（SharePoint等での配布時）
- 通信断絶時は `alert()` にて警告
- データはブラウザ内（localStorage/メモリ）で保持

## 6. 非機能要件

### 6.1 パフォーマンス
- 画面遷移時の応答時間：操作から次の画面表示まで **2秒以内**
- Excel生成時間：最大30ステップのSOPで **5秒以内**
- 画像ペーストからプレビュー表示まで **1秒以内**

### 6.2 セキュリティ
- **クリップボードAPI制約**: `navigator.clipboard.read()` を使用するため **HTTPS配信必須**
- データはブラウザのローカルストレージ（localStorage）とメモリ上で保持
- 画像データはブラウザのメモリ上でのみ保持し、ローカルファイルシステムへの保存は行わない（エクスポート時を除く）

### 6.3 ブラウザ互換性
- **Microsoft Edge (最新版)** を推奨
- モバイルブラウザは対象外

### 6.4 データ永続性
- テンプレートデータ：localStorageへ自動保存
- ブラウザのキャッシュクリア等によりデータが消失する可能性あり
- 実績データはエクスポートでのみ外部保存

### 6.5 アクセシビリティ
- キーボード操作による全機能の利用を可能とする
- スクリーンリーダー対応については将来的な検討課題とする

### 6.6 UI/UXデザイン要件
- 全画面において**美しく洗練されたデザイン**を適用する
- 色彩、フォント、余白、アニメーション等はモダンなWebアプリケーションに準じた品質とする
- 一貫性のあるデザインシステム（カラーパレット、タイポグラフィ、コンポーネントスタイル）を整備する
- **全ページの上部に統一されたメニューバー（ナビゲーションバー）を1つだけ配置する**
  - メニューバーには「TOP」「SOP作成」「実施」の3つの主要画面へのリンク/ボタンを配置
  - 全画面で同一のデザイン・配置とし、統一感を確保する
  - 現在の画面が視覚的に識別できるアクティブ表示を行う
  - **メニューバーは1つに統一し、重複したバー（app-header等）は表示しない**
  - **メニューバー内の不要なトグルボタン（管理画面/実施画面）は削除する**
- **メニューバーのアクティブ状態と実際の表示画面を常に一致させる**
  - メニュー押下時の画面遷移でアクティブ表示が正しく更新されることを保証する
  - 画面復元（リロード）時もアクティブ表示が正しい画面と一致する
- **画面遷移関係を明確に定義する（4.2節参照）**
  - 各画面間の遷移トリガーと動作を一覧化する
  - 未保存状態での遷移は確認ダイアログを経由する
  - メニューバーからの遷移も含めて一貫性を確保する
- **メニューバーのブランド部分（「SOP管理システム」）をクリックするとTOP画面（SOP一覧画面）へ遷移する**
  - ブランドテキストをリンク/ボタンとして機能させ、クリックで `showSelectionView()` を呼び出す
  - 遷移時は未保存チェック（`confirmUnsavedChanges`）を経由する
- **各画面の余白は画面サイズに合わせて活用し、左右の空白を適切に使用して閲覧性を高める**

## 7. 出力成果物要件 (Excel Export)

### 7.1 フォーマット
- **.xlsx (OpenXML形式)**

### 7.2 レイアウト定義
- シート1枚に全工程を縦に並べる
- **列構成**: [No, 作業内容, 実施時刻, 判定, スキップ理由, コメント, 画像]
- **フォント**: 游ゴシック 11pt
- **罫線**: 標準的な細実線
- **画像配置**: 画像列には複数枚の画像を1列に縦に並べて埋め込み（セル結合で複数行にまたがる形）

### 7.3 画像最適化
- 画像添付時にJavaScriptにて以下を実施
  - **最大幅1280px** へのリサイズ
  - **JPEG品質係数0.8** での圧縮（または同等の圧縮率）
- ファイルサイズが大きくなりすぎないよう制御

## 8. 運用・ワークフロー

### 8.1 作成・実施フロー
1. 管理者が作成画面でSOPを新規作成
2. 各SOPにステップを定義し、設定を編集
3. 作成者がTeams等でファイルを共有
4. 作業者がSOPを開き、ステップごとに作業を実行・記録
5. 全ステップ完了後、実績データをExcel出力

### 8.2 データ共有方法
- テンプレートデータはlocalStorageに保存（同一ブラウザ内で永続化）
- 実績データはExcelファイルとしてエクスポートして共有
- 別PCへのデータ移行はエクスポート/インポート機能で対応
- SOP一覧画面(選択画面)にJSONファイルからインポートするUIを提供する

### 8.3 権限管理
- ファイルシステムまたはSharePointの標準権限に依存
- 特殊なシステム内権限制御は実装しない

## 9. ユースケース

### 9.1 基本シナリオ
1. **SOP作成**: 作成者が作成画面で新規SOPを作成し、ステップを定義する
2. **SOP保存**: localStorageに自動保存され、ブラウザを閉じてもデータが保持される
3. **SOP実施**: 作業者が実施画面でSOPを開き、ステップごとに作業を実行・記録
4. **実績出力**: 全ステップ完了後、実績データをExcelファイルとしてエクスポート

### 9.2 操作動線の明確化
- 画面遷移・ボタン操作・入力操作のユースケースを定義し、作業者の動線を考慮したレイアウト・配置とする
- 名称は実態に沿ったファイル名称・画面名称・ボタン名称を採用する

### 9.3 例外シナリオ
| シナリオ | 期待動作 |
|----------|----------|
| ネットワーク断発生 | alert()で警告（データはlocalStorageに保持） |
| 画像ペースト失敗 | エラーメッセージを表示し、再ペーストを促す |
| ブラウザのキャッシュクリア | localStorageのデータが消失（運用でバックアップ推奨） |
| 実施途中でブラウザ閉じる | localStorageに保存済みデータは維持される（次回開時に復元） |
