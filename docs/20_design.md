# 基本・詳細設計書

## 1. 設計方針

### 1.1 全体方針
- 既存のHTML/CSS/JS構成を維持し、必要な部分のみを修正
- フィードバック項目に優先度をつけて段階的に実装
- GitHub Pagesでの動作を前提とした設計
- ファイル構成は変更せず、既存の資産を活用

### 1.2 デザイン統一
- 全画面でカード形式のデザインを採用
- メニューバーは1つに統一
- ボタンレイアウトは横並びを基本とし、余分な空白を排除
- 画面サイズに応じて余白を可変とし、中央寄せで表示
- 全画面のデザインを統一し、洗練されたドキュメントレイアウトを適用

### 1.3 フィードバック履歴管理
- フィードバック履歴の管理機能は実装しない（不要）

### 1.4 アイコン統一
Google Material Icons を採用し、ボタンアイコンを以下の名称で表示する

- 削除ボタン: `delete`
- 編集ボタン: `edit`
- エクスポートボタン: `file_download`
- 実施ボタン: `play_arrow`
- キャンセルボタン: `close`
- 保存ボタン: `save`

  "steps": [

## 3. SOP一覧画面設計

### 3.1 レイアウト
- 横長カード型デザイン（横方向1つ、縦に並べる）
- ステップ一覧・実施作業一覧とレイアウト統一
- 各SOPカードに編集・削除・エクスポート・実施ボタンをアイコン表示
- 新規作成ボタンとJSON読み込みボタンはコンパクトな横並びレイアウト
- カードヘッダーエリアとSOP一覧エリアは1つのカードに統合

### 3.2 画面遷移
- 「+ 新規SOP作成」ボタン → 作成画面（空のSOP）
- 編集アイコン → 作成画面（既存SOP）
- 実施アイコン → 実施開始画面
- エクスポートアイコン → JSONファイルダウンロード
- 削除アイコン → 確認後削除

## 4. 作成画面設計

### 4.1 レイアウト変更
- プレビューボタンを廃止
- ステップ編集エリアをカード形式で統一
- 詳細エリアの開閉、保存、キャンセル、削除ボタンを横並びに配置
- 削除ボタンを保存・キャンセルボタンの近くに配置
- ステップ番号は編集時も見えるように固定表示

### 4.2 ステップ詳細エリア
- 作業指示とコメントを縦に並べ、その横に画像を配置
- 画像貼り付けエリアを詳細エリア内に含める
- 参考画像欄を縦に長く確保（余計な空白を排除）
- 開閉ボタン（▼/▲）と操作ボタンを横並びに配置
- 画像クリックで拡大表示
- 画像に削除ボタン（×）を表示
- 画像の貼り付けが確実に動作するよう制御

### 4.3 詳細エリア開閉制御の修正
- step-item のクリックハンドラで、クリック対象が `.step-detail` 配下の要素（textarea, input等）の場合は詳細を toggle しない
- 実装: `e.target.closest('.step-detail')` が存在する場合は toggle 処理をスキップ

### 4.4 新規ステップ作成時の詳細エリア自動展開
- `addStep()` で空ステップ追加後、詳細エリア（step-detail）を自動的に表示状態にする
- 詳細エリア内の instruction, comment, images, evidence 設定をすべて編集可能にする

### 4.5 保存ボタンの動的制御
- 詳細エリア内の保存ボタン（detail-save-btn）も disabled 制御する
- 初期表示時: disabled
- いずれかの入力が変更された時: enabled
- 保存後: disabled に戻す
- 変更検知対象: 作業指示、補足コメント、エビデンスチェック、エビデンス説明、画像の追加/削除

### 4.6 キャンセル操作
- 詳細エリアのキャンセルボタン押下時は編集前の状態に復元
- 編集中の内容は保存されず、元の値に戻る

### 4.7 ステップ削除
- 削除ボタンを各ステップ詳細エリア内に配置
- 削除後は詳細エリアを自動的に閉じる

### 4.8 エビデンス設定
- 各ステップにエビデンス要否（チェックボックス）を追加
- エビデンス説明（テキスト入力欄）を追加
- 常時ONの制御: 時刻記録必須、OK/NG判定必須、スキップ許可

### 4.9 ボタンレイアウト
- 詳細エリアの保存・キャンセル・削除ボタンは `flex:1` による均等割り付けを解除
- 各ボタンを内容幅（auto）で表示し、余計な空白を排除
- ボタン間の gap は 8px を維持
- 保存・キャンセル・削除ボタンはアイコン+テキスト表示

### 4.10 SOP編集画面のボタン
- 「キャンセル」ボタンを常時表示（display:none にしない）
- 「選択画面へ」ボタン押下時は `confirmUnsavedChanges` を経由して確認ダイアログを表示
- 確認ダイアログの選択肢:
  - 「保存して戻る」: SOPを保存して一覧へ戻る
  - 「破棄して戻る」: 保存せず一覧へ戻る
  - 「キャンセル」: 編集画面に留まる
- SOP保存時のポップアップ2重表示を防止

### 4.11 画面名称
- 「管理者画面」ではなく「作成画面」という名称を使用
- メニューバーの表示: 「SOP作成」
- 画面上のタイトル表示: 「作成画面」

### 4.12 作業指示内容の必須項目化
- ステップ編集時、「作業指示内容」を必須項目としてバリデーション

### 4.13 ステップ番号の編集時表示維持
- インライン編集（`startInlineEdit`）がイベントハンドラから呼び出されていないため、クリック時の動作を詳細エリア開閉に統一する
- ステップ番号（`.step-index`）は編集時も常に表示されるようにCSSで保証する
- `.step-item.editing` 状態でも `.step-index` が非表示にならないようにする

### 4.14 画像ペーストの確実な動作
- `_attachDetailPasteHandlers` 関数を `renderStepsList()` の末尾で呼び出す
- 詳細エリア描画後、各画像アップロードエリアにペーストハンドラが確実にアタッチされるようにする
- `data-paste-attached` 属性で重複アタッチを防止

### 4.15 保存ボタンの重複ハンドラ防止
- `showAdminView()` 内の `save-sop-btn` への click ハンドラ登録を削除し、`setupEventListeners()` の1箇所のみに集約する
- これにより保存時に alert が2重表示される問題を修正する

### 4.16 参考画像欄の縦方向拡大
- `.step-detail-right` の幅制限を見直し、画像表示エリアを縦方向に拡大する
- 画像アップロードエリアの `min-height` を増加させ、余計な空白を排除する
- 画像サムネイルのグリッドレイアウトを調整し、画像を効率的に配置する

### 4.17 参考画像複数貼り付け防止（フィードバック対応）
- ペーストイベントハンドラ内で、1回のペースト操作で1枚の画像のみが追加されることを保証する
- `clipboard.read()` の結果が複数アイテムを含む場合でも、最初の画像のみを処理する
- ペースト処理の重複実行を防止するため、処理中フラグを設ける

### 4.18 画像編集後の保存ボタン有効化（フィードバック対応）
- 画像の追加・削除時に `markStepDirty()` を呼び出し、ステップのdirty状態を確実に更新する
- `_attachDetailPasteHandlers` 内の画像追加処理の末尾で `markStepDirty()` を実行する
- 画像削除ボタンのハンドラ内でも同様に `markStepDirty()` を実行する

## 5. 実施画面設計

### 5.1 レイアウト変更
- 全ステップを一覧表示するスクロール形式に変更
- 各ステップを上下2段構成に変更:
  - 上段: 指示内容、参照画像、補足コメント（ステップ情報）
  - 下段: 完了日付・時刻、判定ボタン（OK/NG/スキップ）、作業コメント、スキップ理由入力、エビデンス画像貼り付け（実施情報）
- 作業動線に沿って上から下へ流れるレイアウト

### 5.2 ステップ番号表示
- SOP作成画面のステップ番号と同じデザインを適用

### 5.3 入力項目
- 完了日付・時刻: OK/NG/スキップ押下時に自動記録
- OK/NG判定: トグル形式のボタン選択（下段）
- 画像添付: Ctrl+Vで貼り付け、削除ボタン（×）で削除（下段）
- 作業コメント: テキスト入力欄（下段）
- スキップ理由: 事前に入力欄を表示（下段）

### 5.4 画像管理
- 貼り付けエリアに「Ctrl+Vで貼り付け」のプレースホルダーを表示
- 「ペースト」ボタンは非表示
- 貼り付けた画像には削除ボタン（×）を表示
- 参照画像クリックで拡大表示
- エビデンス画像貼り付け欄の謎の枠を削除
- エビデンス画像の貼り付けが確実に動作するよう修正

### 5.5 エビデンス貼り付け欄の二重枠修正
- 実施画面のエビデンス領域で、`image-upload-area`（破線枠）と `captured-images`（破線枠）が入れ子になっている構造を解消する
- `image-upload-area` の破線枠を削除し、`captured-images` のみを表示する
- または `captured-images` の破線枠を削除し、外側の `image-upload-area` のみを表示する
- プレースホルダーテキスト「Ctrl+Vで画像を貼り付け」は維持する

### 5.6 スキップ機能
- スキップ理由入力欄をあらかじめ表示
- 未入力でスキップボタン押下時はエラーメッセージを表示
- スキップ時も完了日付・時刻を自動記録

### 5.7 作業者名
- 実施開始画面および実施画面に作業者名の入力欄は不要
- 実施開始画面は「開始」ボタンのみ

### 5.8 実施記録一覧表示
- 各ステップの実施記録（判定・時刻・コメント・画像）を一覧で確認可能
- 実施記録は実施画面と同じ上下2段構成で詳細表示する

### 5.9 実施記録重複防止（フィードバック対応）
- 判定ボタン（OK/NG/スキップ）押下時のイベントハンドラ重複登録を防止する
- 各ステップの実施記録作成処理を冪等にする
- ボタン押下時に処理中フラグを設け、複数回の記録作成を防止する
- 既存の実施記録がある場合は新規作成せず更新する方式に変更する

## 6. 状態管理設計

### 6.1 リロード耐性
- 作成画面で編集中の場合: 前回のSOPを復元
- 実施画面で作業中の場合: 前回のステップ位置と実績データを復元
- その他の場合: TOP画面を表示

### 6.2 未保存検知
- 編集中の変更を検知し、画面離脱時に確認ダイアログを表示
- 確認ダイアログの選択肢: 保存して戻る、破棄して戻る、キャンセル

## 8. 実装上の注意点

### 8.1 既存資産の活用
- SheetJS (xlsx) はCDN版を使用
- 画像圧縮はCanvas APIを使用
- フレームワークは使用せずVanilla JSで実装

### 8.2 パフォーマンス
- 画像ペーストからプレビュー表示まで1秒以内
- 画面遷移は2秒以内
- Excel生成は5秒以内（30ステップまで）

### 8.3 ブラウザ制約
- Microsoft Edge最新版を推奨
- HTTPS配信必須（クリップボードAPI使用のため）
- モバイルブラウザは対象外

## 10. リスクと対策

### 10.1 技術的リスク
- クリップボードAPIのブラウザ互換性 → Edgeに限定
- localStorage容量制限 → 画像リサイズ・圧縮で対策
- Excel生成ライブラリのメモリ使用 → 大規模データ時の分割生成を検討

### 10.2 要件リスク
- フィードバック内容の解釈違い → フェーズ0で確認済み
- 既存機能への影響 → 回帰テストで検証
