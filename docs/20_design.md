# 基本・詳細設計書

## 1. 設計方針

### 1.1 全体方針
- 既存のHTML/CSS/JS構成を維持し、必要な部分のみを修正
- フィードバック項目に優先度をつけて段階的に実装
- GitHub Pagesでの動作を前提とした設計
- ファイル構成は変更せず、既存の資産を活用

### 1.2 デザイン統一
- 全画面でカード形式のデザインを採用
- メニューバーは1つに統一
- ボタンレイアウトは横並びを基本とし、余分な空白を排除
- 画面サイズに応じて余白を可変とし、中央寄せで表示

## 2. データ構造設計

### 2.1 スキーマ変更
```json
{
  "sop_id": "string",
  "sop_title": "string",
  "steps": [
    {
      "step_index": "integer",
      "instruction": "string",
      "media_enabled": "boolean",
      "require_time": "boolean",
      "require_judgment": "boolean",
      "skip_enabled": "boolean",
      "evidence_required": "boolean",
      "evidence_description": "string",
      "images": ["base64"],
      "comment": "string"
    }
  ]
}
```

### 2.2 変更点
- `evidence_required`: エビデンスの要否を追加
- `evidence_description`: 取得するエビデンスの説明を追加

## 3. SOP一覧画面設計

### 3.1 レイアウト
- ヘッダーエリアと一覧エリアを1つのカードに統合
- 新規作成ボタンとJSON読み込みボタンは横並びに配置
- 各SOPは横長のカード形式で表示
- ステップ一覧と同じデザインパターンを適用

### 3.2 コンポーネント構成
- カードヘッダー: システムタイトル（メニューバーに分離）
- カードボディ: 新規作成ボタン、JSON読み込みボタン、SOP一覧

## 4. 作成画面設計

### 4.1 レイアウト変更
- プレビューボタンを廃止
- ステップ編集エリアをカード形式で統一
- 詳細エリアの開閉、保存、キャンセル、削除ボタンを横並びに配置
- 削除ボタンを保存・キャンセルボタンの近くに配置

### 4.2 ステップ詳細エリア
- 作業指示とコメントを縦に並べ、その横に画像を配置
- 画像貼り付けエリアを詳細エリア内に含める
- 開閉ボタン（▼/▲）と操作ボタンを横並びに配置
- 画像クリックで拡大表示
- 画像に削除ボタン（×）を表示

### 4.3 新規ステップ作成
- ポップアップを廃止し、一覧最下部に空ステップを直接追加
- 1回の操作で1ステップのみ追加

### 4.4 画像貼り付け
- Ctrl+Vでの貼り付けを確実に動作させる
- 詳細エリアの開閉制御を見直し、貼り付け前に詳細が閉じないようにする
- 画像アップロードエリアを十分なサイズで確保

### 4.5 保存ボタンの動的制御
- 変更検知対象: 作業指示、補足コメント、画像の追加/削除
- 変更がない場合は保存ボタンをdisabled状態にする
- 詳細エリアの保存時や画像操作時にリアルタイムで更新

### 4.6 キャンセル操作
- 詳細エリアのキャンセルボタン押下時は編集前の状態に復元
- 編集中の内容は保存されず、元の値に戻る

### 4.7 ステップ削除
- 削除ボタンを各ステップ詳細エリア内に配置
- 削除後は詳細エリアを自動的に閉じる

### 4.8 エビデンス設定
- 各ステップにエビデンス要否（チェックボックス）を追加
- エビデンス説明（テキスト入力欄）を追加
- 常時ONの制御: 時刻記録必須、OK/NG判定必須、スキップ許可

## 5. 実施画面設計

### 5.1 レイアウト変更
- 全ステップを一覧表示するスクロール形式に変更
- 各ステップを左右2カラムに分割
  - 左カラム: 指示内容、補足コメント、作業コメント入力、スキップ理由入力、OK/NG/スキップボタン
  - 右カラム: 参照画像、エビデンス画像貼り付けエリア
- 上側にステップ情報、下側に実施情報を配置

### 5.2 入力項目
- 完了日付・時刻: OK/NG/スキップ押下時に自動記録
- OK/NG判定: トグル形式のボタン選択
- 画像添付: Ctrl+Vで貼り付け、削除ボタン（×）で削除
- 作業コメント: テキスト入力欄
- スキップ理由: 事前に入力欄を表示

### 5.3 画像管理
- 貼り付けエリアに「Ctrl+Vで貼り付け」のプレースホルダーを表示
- 「ペースト」ボタンは非表示
- 貼り付けた画像には削除ボタン（×）を表示
- 参照画像クリックで拡大表示

### 5.4 スキップ機能
- スキップ理由入力欄をあらかじめ表示
- 未入力でスキップボタン押下時はエラーメッセージを表示
- スキップ時も完了日付・時刻を自動記録

### 5.5 作業者名
- 実施開始画面および実施画面に作業者名の入力欄は不要
- 実施開始画面は「開始」ボタンのみ

## 6. 状態管理設計

### 6.1 リロード耐性
- 作成画面で編集中の場合: 前回のSOPを復元
- 実施画面で作業中の場合: 前回のステップ位置と実績データを復元
- その他の場合: TOP画面を表示

### 6.2 未保存検知
- 編集中の変更を検知し、画面離脱時に確認ダイアログを表示
- 確認ダイアログの選択肢: 保存して戻る、破棄して戻る、キャンセル

- 最大幅: 1200px

- 画面サイズに応じて余白を可変

## 8. 実装上の注意点

### 8.1 既存資産の活用
- SheetJS (xlsx) はCDN版を使用
- 画像圧縮はCanvas APIを使用
- フレームワークは使用せずVanilla JSで実装

### 8.2 パフォーマンス
- 画像ペーストからプレビュー表示まで1秒以内
- 画面遷移は2秒以内
- Excel生成は5秒以内（30ステップまで）

### 8.3 ブラウザ制約
- Microsoft Edge最新版を推奨
- HTTPS配信必須（クリップボードAPI使用のため）
- モバイルブラウザは対象外

## 9. テスト戦略

### 9.1 テスト対象
- フィードバック項目の全件実装
- 既存機能の回帰テスト
- 画面レイアウトの検証
- データ永続化の検証

### 9.2 テスト環境
- Microsoft Edge最新版
- GitHub Pages相当のHTTPS環境

## 10. リスクと対策

### 10.1 技術的リスク
- クリップボードAPIのブラウザ互換性 → Edgeに限定
- localStorage容量制限 → 画像リサイズ・圧縮で対策
- Excel生成ライブラリのメモリ使用 → 大規模データ時の分割生成を検討

### 10.2 要件リスク
- フィードバック内容の解釈違い → フェーズ0で確認済み
- 既存機能への影響 → 回帰テストで検証

## 11. 移行手順（実装影響範囲）
- ステップ一覧のDOM構造を変更し、カード形式に統一
- 画像貼り付けの制御フローを修正
- 保存ボタンの状態管理ロジックを更新
- データ構造に`evidence_required`と`evidence_description`を追加
- 既存テストケースは保持し、新規テストは追記形式で追加
